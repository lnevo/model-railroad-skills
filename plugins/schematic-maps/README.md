# Schematic maps (separate plugin)

`schematic-maps` draws a model railroad's track as one clean schematic sheet: a band for each level, the main line level through every switch, yard ladders stepped diagonally, loops, helix tracks, lettered connectors between levels, and signal masts. It reads the track plan's AnyRail "export to JMRI" file and, for masts, a JMRI Layout Editor panel; it writes an SVG and checks it for crossing lines and overlapping labels.

It runs a Python command and writes files you choose, so it is a separate install.

```
claude plugin install schematic-maps@model-railroad-skills
```

The command uses only the Python 3.11+ standard library. No fonts are read: text is measured with a bundled table, so the same input draws the same sheet on every machine.

## Use

`<plugin>/bin/schematic` runs `python3 -m schematic` with the plugin folder on the module path.

```
schematic plan plan.xml graph.json --parts parts.json
schematic pieces plan.xml [--json pieces.json] [--px-per-cm X]                every track piece, told by its geometry
schematic signals tables.xml graph.json NAME NAME.signals.json --data DIR --numbers numbers.csv --lengths lengths.csv
schematic draw sheet.svg --data DIR graph.json:NAME
schematic report --data DIR graph.json:NAME
schematic fingerprint golden.json --data DIR graph.json:NAME
schematic detail details/ --data DIR graph.json:NAME                      one sheet per station of the `stations` preference
schematic detail yard.svg --data DIR graph.json:NAME --station "Yard"      one station
schematic detail pair.svg --data DIR graph.json:NAME --switches 11 12 --name "Pair"   any group of switches
schematic cats panel.xml --data DIR graph.json:NAME [--band "Main"] [--bindings b.json] [--templates-from desk.xml]
                        [--cells-per-unit 1] [--fit 63x36]                a CATS Designer panel from the same grid
schematic le panel.xml --data DIR graph.json:NAME [--names names.json] [--panel NAME] [--fit 1900x1140]   a JMRI Layout Editor panel
schematic check sheet.svg --list
```

Interlocking limits are optional: `control_points` in the plan overrides names each control point, an optional short code and the switches it covers. Detail sheets (not the overall sheet) draw square brackets across the tracks at its outer ends and the quoted name (see style rule 10), for each control point whose switches are all on the sheet.

Layer files in `DIR`: `NAME.plan_overrides.json` (facts about the railroad), `NAME.signals.json` (generated), `NAME.preferences.json` (the look, optional). Page folding is a preference (`fold: true` or `fold_min_scale` in the preferences file): a band too long to read at Letter size is cut into rows with CONTINUES arrows. The skill, [`skills/schematic-maps/SKILL.md`](skills/schematic-maps/SKILL.md), walks through the overrides and the checks.

Since 0.1.51 `schematic pieces` lists every track piece in AnyRail's JMRI export by its geometry, never by a part name: straights by length, curves by radius and angle, flex by length and tightest radius, turnouts by hand, shape (straight, curved or wye), straight route, diverging chord, diverging angle and frog number, and double crossovers by length and track spacing. Pieces of one kind are counted on one line, so the same part from two libraries reads as one. What it cannot read (level crossings, slips, turntables, elliptical arcs, other turnout types) is listed with the reason. The new `anyrail-track-plans` skill says which AnyRail feature gives which fact and how to tell pieces apart. No change to the other commands: `plan_reader` shares its turnout leg helper with it, and a turnout attribute that is not a number now stops with a message naming it.

Since 0.1.49 each kind of layer file may also be one file for every input, `DIR/<kind>.json` (`plan_overrides.json`, `preferences.json`, `signals.json`, `hints.json`) holding `"_sections": true`, whose other top-level keys are the input names, each holding what `NAME.<kind>.json` would. A `<kind>.json` without that key is not a layer file and is not read. An input's own file and its section at once stops the run (`LayerError` names both), so a railroad that keeps signals in `signals.json` puts each fresh `signals` command output into its section rather than writing `NAME.signals.json`; a combined file with no section for an input gives it nothing of that kind, as a missing file does; keys starting with `_` are notes, and an input name may not start with `_`. A layer that is not a JSON object, and a signals layer with no `signals` list, stop with the file named. The cache key covers only the sections of the inputs being built, and leaves the title block fields out of each preferences section. Railroads that keep one file per input read as before.

Since 0.1.48 a three-way part in the plan is drawn tight and split on the Layout Editor panel without a preference. The plan reader keys each junction by the export's turnout ident, and AnyRail exports one three-way part as two turnouts `TO_3W<id>-1` and `TO_3W<id>-2` joined by a short track (other keys that merely end in `-1` and `-2` are no three-way part); when each half is in a single crossover of its own, those two crossovers are drawn as `tight_crossovers` and `split_crossovers` naming them would draw them, the crossover holding half 1 first, and the log says so (`<band>: three-way part <part>: crossovers 7 and 8 drawn tight and split`). Like those arguments it applies to a panel at a given grid on a band with a crossover run (`crossover_run`, or its `le_crossover_angle`); a fitted panel, a band with no run, and a part with only one half in a crossover are drawn as usual and logged, and on a fitted panel or a band with no run the part is not checked, so such a panel draws as in 0.1.47. Behaviour change, where the rule applies: a `tight_crossovers` or `split_crossovers` argument, or an `le_tight_crossovers` or `le_split_crossovers` preference, that names such a crossover now stops the run (the plan decides it; remove the entry), and so do a part's two halves that are not two switches joined by exactly one track, both halves in one crossover, one crossover holding halves of two parts, and a crossover number that names two crossovers of the band (relabel one). Panels whose preferences named exactly these pairs draw the same once the entries are removed.

Also in 0.1.48, `cats.faults(P, fit)` lists a finished CATS panel's desk faults by their cause, one line each: two blocks landing in one cell (a block boundary on a switch's points, on a crossing, or where two blocks in one cell reach one edge, which CATS cannot hold: it would drop the points), named by the band the cell is drawn on, blocks, cell and switch, once per boundary; and, with `fit`, a desk wider or taller than its window, with the columns each band takes. `schematic cats` prints `desk faults: N` and writes nothing when there is one. The error for a desk whose track still reaches past `--fit` once every plain column is out now says the desk is wider than its window and gives each band's columns. Nothing is drawn differently.

Since 0.1.47 an override names a junction as `label@label` too: `23@1` is the junction labelled 23 that a track joins to the junction labelled 1. It reaches a crossover or three-way half that no named track leaves yet, such as the first track a `name` edit names there, so that edit no longer needs the plan's part numbers. The part after @ is a track name, as before, or a neighbour's label (a label only, not a part number). When it is both and the two readings answer different junctions, the reference stops instead of picking one, so naming a track later cannot quietly change what an existing reference means. A reference both halves answer, or none, stops as before.

Since 0.1.46 a plain turnout's switch number on the Layout Editor panel has two more kinds of spot. It may stand in its frog: the wedge between its two legs past where they meet, the box against either leg and a few pixels off it. And it may stack further out on a side, past a mast icon or label that stands above or below the turnout in the column the number would take, centred on the turnout or over what it stacks past. Both are tried after the spots around the turnout at the same distance, ranked by their own distance, so the old spots keep their order and a number found clean nearer keeps its place; both are judged like any spot (clear of track, the other leg and every box, no nearer another turnout). A crossover drawn as one crossover keeps its number around the crossover as before; one drawn as two turnouts on its one name (split names) may take these spots like a plain turnout. Panels whose numbers found a clean spot at their first distances draw as before; others may take a nearer spot in a frog or past a mast, and the block contents icons and names placed after them may move with them. A switch in `numbers_below` gets only the new spots below its turnout, so a frog or a mast above can no longer take its number above the turnout before the old spots below it further out.

Also in 0.1.46, on a band with `names_last`, a track name that would be left out now makes room where it can: it takes its first spot that only placed block contents icons keep from being clean when each of those icons finds another clean spot (at its full reserve, else its short one) or makes room the same way one step further. Only then may switch numbers and other names move like that too. Before a left-out name is put first in a later round (the lead), an item that round leaves with no spot may make room the same way. Each move is logged ("room made"), nothing is ever left out or moved for nothing, and a name with no such spot is still left out. Placing by band, only the band's own items move: what an earlier band placed stands where it is, like the drawing. Two track names with one text on a band are still two items, each moved on its own. Panels whose labels all placed are drawn as before.

Also in 0.1.46 a signals file entry may have `"leg"`: the leg (port, as the plan graph names it) of the switch where the mast's part of its run starts. It is needed on a loop, a run whose two ends are both legs of one switch, since a balloon loop is drawn as two halves that both end at that switch: every mast on a loop must name the leg its half leaves from, a mast measured from the loop's turnback included. The sheet and the CATS desk draw the mast on that half. A loop mast with no leg or a wrong one stops the drawing with an error, as does a leg on any other run that is not where the run meets its toward switch. `schematic signals` writes the leg for every loop mast from the panel's leg, and lists the mast as unplaced when that leg is not one of the loop's.

Since 0.1.45 a helix track whose ends on both levels are plan cuts (track ends the input graphs mark `cut` with the height the levels were parted at, the same on both; `schematic plan` marks none, so a tool that gives each level its share of the helix run writes them) carries the milepost count straight on with no `helix_length_in`: the levels' own graphs hold the whole run. Two cut ends at different heights stop. A length given for such a track is still added, and a helix track with an uncut end still needs one. Railroads with no cut ends count as before. Also in 0.1.45: the preference `turnbacks` (layer 3, a list of track names) makes each named track a turnback in every orientation the layout tries, so a sheet keeps the folds its owner approved when new plan lengths would make another drawing cheaper; a name no track of the input carries, or one no orientation can turn back, stops. And on the Layout Editor panel a helix end's "HELIX TO" label that lies on a track beside its circle goes above the circle, else below it (logged); a label clear at its own spot is drawn as before. And `le_labels` may list `crowded_block_contents`: blocks whose contents icon, when no clean spot is left, is drawn at its first spot anyway, overlaps allowed and logged (the check passes it over), where `optional_block_contents` would leave it out.

Since 0.1.50 the preference `track_labels` (layer 3, an object of track name to label) draws each named track's label in place of its name on every output: the sheet, the station detail sheets, the Layout Editor panel and the CATS desk, wherever a track name is printed or measured (its room in the columns, its label, a detail sheet's cut, the panel's name room and labels, the desk's labels). It is sheet-wide, as `helix_style` is: one input may give it for every input, and two inputs giving one track two labels stop, as do a key no track of the sheet has, a value that is not an object of non-empty strings, and two tracks that would draw the same text (a label and another track's label or name). Its keys are track names, so one starting with `_` is a name, not a note. The names themselves stay what the rest of the tool reads (routes, turnbacks, stations, the helix pairing between levels, block names and the desk's bindings). Helix letters (H1, H2, ...) follow the names drawn: every helix track of the sheet, the `helix` preference's and any an `end` edit makes, sorts by its label, then its name, so a track renamed and labelled with its old name draws byte for byte as before. With no labels the drawing is unchanged, except that a helix track only an `end` edit makes now takes its letter in that order rather than after the declared ones.

In 0.1.46 a block drawn on two bands (a helix track joined as one block, as the default names give it and a names file may too) has its block contents icon placed on its own band only, the band `block_band` gives it, so that band's extent and `le_title_clear` no longer reach into the other band.

Since 0.1.44 `schematic plan` measures track in the export's own scale when given parts: it fits one scale (and offset) between the export's switches and the parts list and turns every length into centimetres with it, so an export at any size gives the same lengths. Without parts it uses AnyRail's usual 12 px per inch and says so in the notes. It stops when the x and y scales differ by more than 3%, or when fewer than three switches line up.

Mileposts are a preference (`mileposts: true`, or `{"step": 0.25}` in miles) and need layer 1 facts: `milepost_origin` (`{"switch": "1", "milepost": 0.0}`), `scale_ratio` (87.1 for HO), `helix_length_in` to carry the count through a helix, and optionally `milepost_route`. The count runs in scale miles along the main route from the origin using the same lengths as capacity; ticks sit where it crosses a multiple of the step. With the preference off the drawing is unchanged. See rule 19 in `skills/schematic-maps/references/style.md`.

Solving a sheet is the slow part of every command. `SCHEMATIC_CACHE=<folder>` keeps each solved sheet in that folder and reads it back when the same inputs are built again: the key covers the source of the code the solve runs (not the Layout Editor or CATS modules), the graphs, the layer files and the preference and hint switches, so any change to them solves again. The title block's `date`, `revision` and `sheet` are left out of the key: a hit takes them from the files and draws the page again. `le.panel` keeps its panels there too, and the grid a `fit` settles on apart from them, so a change to the label layer's inputs alone (`extras`, `labels_by_band`) draws the panel once instead of searching again. It is off by default. Point it only at a folder you alone write to, since the entries are Python pickles.

## Detail sheets

`schematic detail` draws one station, or a named group of switches, as its own larger sheet, cut from the same solved drawing as the overall sheet so the two agree: same order of tracks, same lengths, same capacity counts and masts. Tracks that leave the cut end in an arrow reading `TO <station>` or `TO SW <number>`. Sheets come from the `detail_sheets` preference (name to switch numbers, which may overlap stations) when present, else the `stations` preference, all of them by default. Stations may overlap; `station_tracks` (plan overrides) limits a station's car total to listed tracks and `station_side` (preferences) puts its bar above or below the band; the object form (`switches`, `tracks`, `side`) also reads. A sheet shows a bar and car total for each station that lies wholly inside it; `detail_max_scale` (default 2) sets how far a sheet is enlarged. One selection writes a file, several write a folder of `<station>.svg`.

In 0.1.43, a single crossover drawn as two turnouts on its one turnout name (no room, more than a row deep, not on two level tracks, or `split_crossovers`) is numbered once on the Layout Editor panel by its crossover number, as one drawn as an RH_XOVER or LH_XOVER is (`7`, not a half's `7A`); `numbers_below` names it by that number too.

Since 0.1.42 a single crossover's halves are paired by switch number, and halves lettered A and B may join by leg B. Halves are labelled alike (`7` and `7`), or lettered A and B, as the prototype letters crossover halves (`7A` and `7B`: the number with one letter after its last digit). Two switches of one number joined directly by one track are one single crossover when that track runs leg C to leg C (labelled alike without a letter, or lettered one A and one B), or leg B to leg C for halves lettered A and B. That track is each half's link (thrown) route, and the half's other leg B or C is its normal (closed) route, on its through track. Halves joined C to C draw as before: link C, normal B. A half laid with its straight route on the crossover's diagonal joins by its leg B, so it is normal on its leg C. The Layout Editor draws such a pair as one RH_XOVER or LH_XOVER, closed with both halves on their through tracks and labelled with its number (`7`); lettered halves joined C to C, two plain turnouts until now, are drawn that way too. A half drawn as a plain turnout (no room, more than a row deep, not on two level tracks, or `split_crossovers`) is normal on its through leg, the CATS panel makes that leg the half's normal route (a CATS binding's `normal` still overrides), and the solver's R8 keeps that leg level rather than leg B. The level cell a track gets before points drawn on a level straight leg (0.1.40) still goes by leg B, so a half joined by its leg B gets none and sheets keep their columns. Since one turnout name with Closed on both through tracks means a half joined by its leg B is Closed on its own diverging route, both panels log `<half> is laid straight on the crossover's diagonal: wire its machine reversed so Closed lines the through route` for each such half. Lettered halves keep an OS block each on both panels (`OS 7A`, `OS 7B`); halves labelled alike share `OS 7`. `tight_crossovers` and `split_crossovers` name a lettered crossover by its number. Behaviour change: a Layout Editor `normal` or `leg_b` name for any half of a single crossover now stops the run (its closed route is both through tracks; remove the entry), however the half is drawn, as one crossover or as two turnouts, so a names file gives the same answer whatever room the drawing finds; `normal` was ignored before for a half drawn as a crossover and obeyed for one drawn as a turnout. Behaviour change: two switches lettered alike (`7A` and `7A`) are no longer paired even when joined C to C (they were before 0.1.42): their letters are ambiguous, and the log says so. Two switches stay two switches, as before, when they are joined at a points (leg A), joined leg B to leg B (back to back on one through track), joined B to C but labelled alike, or not joined. Lettered halves joined by more than one track (a run-around or passing track), with ambiguous letters (two `7A`s joined C to C or B to C, or `7` and `7B`), more than two lettered switches of one number, or a half that would pair with two switches are not paired either; the log says which, and nothing in the pairing stops a run. Two crossovers under one number on a band (`7`/`7` and `7A`/`7B`) are logged, and stop only a `split_crossovers`, `tight_crossovers` or `le_crossover_pairs` entry that names that number. Railroads with no lettered pair draw as before. Also in 0.1.42: on a band with a crossover run (`le_crossover_angle` or `crossover_run`), a single crossover squeezed for room (drawn short of its run by more than 1 px, `XOVER_ROUND`, whole pixels against whole pixels, so a rounding remainder never counts) gets that room the way `le_crossover_pairs` does: its east half and every switch and end at or east of its column (but the band's east edge) slide along the rows, in the rounds that let in mast and name room, until it is no longer squeezed; the log names it by its halves' labels and says how far it slid and its angle (`P.crossover_slides`, by band and track id). The slide never stops a panel: a crossover whose shortfall does not shrink from one round to the next, whose slide would turn a track round or cross lines, whose halves stand in one column, or that has not settled when the rounds run out is drawn as before, squeezed, with the usual `no room for` line and a line saying why it was not slid (one whose slides cannot be undone without such a fault keeps them, logged). A roomy crossover draws exactly as without the rule. On a band with a crossover run, `no room for` is logged in whole pixels and only for a crossover still squeezed past 1 px: one rounded onto its run, or slid until it settled, is not logged as having no room. The run is per row deep, so a crossover two rows deep is drawn as two turnouts on its one turnout name (a JMRI single crossover would take four runs of each track), its diagonal set to the angle leg to leg. `le_crossover_pairs` stays for plain turnouts of different numbers. Bands with no crossover run draw as before.

Since 0.1.41 a double crossover is a block per corner by default, on both panels. The Layout Editor gives each band leg's corner a block, `OS <number>a` to `OS <number>d` (its OS block's name and the leg's letter), so JMRI records no through path between the two legs on one side and Signal Mast Logic discovery pairs no masts across it. The CATS panel gives each corner the same names and the middle of its X a block of its own, `OS <number> X`, with no detector unless the bindings give it one; its X is drawn two cells deep, as with `corners` before. `xover_blocks` (Layout Editor) and `corners` (CATS) still name them. For the old single OS block, give `"xover_blocks": {node: "one"}` (Layout Editor; an `os` name then names that block) and `"corners": "one"` or a `block` (CATS); the log says each crossover drawn as one block. An `os` name for a double crossover with no `xover_blocks` entry stops, since it could mean either. Both panels stop alike when a default corner or middle block is another block's name (a given or bound name, another switch's default OS block such as switch 6a's `OS 6a`, or a track's name) or another double crossover's default (two of one number): name the corners. One CATS switch key that gives `corners` to two double crossovers stops too (bind each by `LABEL/ALIAS`), and so does any name two CATS blocks would share, naming both. A double crossover with no number takes its node id in place of the number (`OS <node>a`, `OS <node> X`) on both panels, as Layout Editor OS blocks do. Panels with a double crossover not named either way redraw, and masts or bindings that named its `OS <number>` block need the corner names or `"one"`.

Since 0.1.40 a switch keeps its straight leg level by default (rule R8): its normal route is drawn level and its diverging leg slopes, unless the main (R5) or a ladder (R6) says otherwise, and except a loop's entry or return, a crossover's diagonal (a short track to another switch's diverging leg C) and the next switch of a ladder. A ladder is now three or more switches linked from the same leg, and a track sloping into points drawn on a level straight leg (other than a ladder's link) gets one level cell first, so the switch does not sit on the diagonal. The `switch` edit takes `branch_leg` ("C", the default, or "B") for an added switch whose branch is its straight leg. Sheets whose switches the search had drawn diverging-level redraw; pin one back with `level_leg`.

Since 0.1.39 two more Layout Editor preferences. `le_crossover_pairs` (`{band: [[switch, switch], ...]}`, also `le.panel`'s `crossover_pairs`) names two plain turnouts of different numbers, joined by one track, that are one crossover on the ground: that track crosses at the band's `le_crossover_angle`, the east switch and everything east of it (but the band's east edge, so the band keeps its width) slid along the rows to give it, in the same rounds that let in mast and name room; `P.pair_angles` and the log give each pair's angle. The label option `name_steps` (a band's, groups of track names) centres each name the same distance in from the west end of its track's level run, half the shortest run in its group, so the names of a fan of tracks step with the tracks' ends. Panels drawn without them come out as before.

Since 0.1.38 `schematic cats --fit` also takes out level columns past the cells it allows (as the `cats_window` preference does), then stops if the panel still shows more; before, only the preference trimmed. When gaps need a compact panel, the command's error now names the gap preferences and where the scale came from (`--cells-per-unit` or `cats_cells_per_unit`); scripts can run the same check with `cats.check_gaps(scale, band_gap, title_gap, names)`.

Since 0.1.37 two more CATS page preferences set the rows between bands: `cats_band_gap` (empty rows between a band's lowest cell and the next band's title; 2 on a compact panel, 3 else, as before) and `cats_title_gap` (empty rows between a band's title and its top track; 1, as before), also `cats.panel`'s `band_gap` and `title_gap`. Fewer rows than the defaults need a compact panel (`cats_cells_per_unit` 1), whose labels are placed around them and their clashes logged. Panels drawn without them come out as before.

Since 0.1.36 a CATS panel's choices can be set as page preferences, read by the command's `cats` and by scripts through `cats.options(page, bands)` (`schematic/cats_prefs.py`): `cats_cells_per_unit` (as `--cells-per-unit`), `cats_helix_blocks` (as `--helix-blocks`) and `cats_window` (`[width, height]` in px, as `--window`). `cats_window` also fits the panel to that window: it takes out level columns past the cells it shows and then stops when the panel shows more, as `--fit` does since 0.1.38, counting CATS's own frame, title, menu and status lines (`cats.CHROME`, 20 x 100 px). Setting an option and its preference both stops, as does a `cats_` key no panel reads, or one a band's own file holds with another value. Panels drawn without them come out as before.

Since 0.1.35 a band's label options can also be set as the band preference `le_band_labels` (`{band: {le_labels key: value}}`), for a preferences file that sets the page and several bands at once, where a flat `le_labels` reaches all of them. A band's options are the defaults, then the page's `le_labels`, then the band's own `le_labels` and its `le_band_labels` entry; a key set in both of the band's own stops (in a file that sets the page and its bands, set a key flat for every band or per band, not both). A new band label option, `hidden_names`, lists track names the Layout Editor panel leaves off: no label and no room kept for one, while the name still names the block and joins a helix, and the sheet keeps it. A listed name on no track of the band stops. Panels drawn without them come out as before.

Since 0.1.34 four more `le.panel` arguments can be set as a band's preferences: `le_tight_crossovers`, `le_split_crossovers`, `le_mast_room` and `le_name_room`. They apply to a panel at a given grid, as `le_crossover_angle` does. A fitted panel draws without them and logs that, and setting both the argument and the preference stops the run. Two page preferences are new for callers: `le_window` (`[width, height]` of the window a panel opens in, read with `le.window(page)`) and `le_row` (the px rows a caller draws at, read with `le.row(page)`; `le.ROW` when not set). Panels drawn without them come out as before.

Since 0.1.33 the Layout Editor panel takes its drawing adjustments as preferences (`le_shift`, `le_longer_straights`, `le_crossover_angle`, `le_title_clear`, `le_stretch`, and `extra_steps`/`extra_follow` in `le_labels`), checked before drawing; see [`references/le-panel.md`](skills/schematic-maps/references/le-panel.md). The `cats` and `le` modules are split into smaller modules with the same public names.

Since 0.1.32 each detail sheet's title block carries the date and revision of the sheet it is cut from (the `date` and `revision` of the last input, which sets the page), whichever input its band comes from, so a station sheet can be matched to its schematic. It has no sheet number.

## CATS panel

`schematic cats` writes a CATS Designer panel (XML) from the solved bands, so a dispatcher panel starts from the same track as the drawing. Each schematic grid unit is two CATS cells, so every 45 degree leg lands on whole cells and each track has a free row below it for its name. Bands stack top to bottom; `--band` keeps the bands whose title starts with the text. It writes the track, switch points with two routes (normal is leg B, or a single crossover half's through leg), a double crossover as its X with a crossing edge, turnbacks as a vertical run, one block per track and one OS block per switch, switch numbers and track names as labels, and logical joins for connector letters and helix tracks that appear on two drawn bands. A turnback joining two differently named tracks is two blocks, parted in the middle of its run (before 0.1.13 it was one block under the first name, and the second name was lost). Every block boundary edge names its block in full. Compress Screen and Automatic Wrapping are turned off in the file.

CATS draws every cell at a fixed 30 pixels and has no zoom, so a panel two cells per unit is often wider than the dispatcher's screen. `--cells-per-unit 1` draws one cell per grid unit, half the size each way, with one empty column on the left: names go on the track (over or under it in its own cells; a yard's parallel tracks are named in one column), each label is placed where it covers no track line, signal or other label at the 30 pixel grid, and a connector or helix label sits beside its end on its own row (else over a connector's or under a helix track's last level cells), without "(JOINED)". OS blocks end a whole step past the points where the track allows, else one cell (mid-slope). Bound masts' gaps slide along their own tracks, between the same two blocks, so a control point's masts stand in one column per direction (a gantry) and out of switch cells. Each mast is then drawn at its clearest spot: lamps pointing the way of the move, on its right-hand side, clear of track, points and other masts. The rules and the renders behind them are in [`skills/schematic-maps/references/cats-signals.md`](skills/schematic-maps/references/cats-signals.md). To keep the OS blocks of switches joined by a one-unit level track apart, that grid column gets a second cell (a slope across it takes the extra cell as level track at a bend); a column that cannot widen (a one-row slope from points to points crosses it) is logged and its switches share an OS block. `--fit COLSxROWS` stops the run when the panel shows more cells than that: 63x36 for a 1900 x 1200 screen, allowing about 100 pixels for the menu and title bars.

Without `--bindings` the panel has no sensor or turnout bindings and no signals; open it in the Designer to add them. `--bindings FILE.json` ties it to the layout's devices:

```json
{"switches": {"3":   {"block": "OS Switch 3", "normal": "B",
                      "routes": {"B": {"ROUTECOMMAND":   {"DECADDR": "12", "JMRIPREFIX": "IT", "USER_NAME": "Switch 3", "command": "close"},
                                       "SELECTEDREPORT": {"DECADDR": "12", "JMRIPREFIX": "IT", "USER_NAME": "Switch 3", "command": "close"}},
                                 "C": {"ROUTECOMMAND":   {"DECADDR": "12", "JMRIPREFIX": "IT", "command": "throw"}}}},
              "7/7b": {"block": "OS Switch 7b"}},
 "blocks":   {"Main": {"name": "Track Main", "station": "Main", "discipline": "CTC",
                       "occupied":   {"DECADDR": "40", "JMRIPREFIX": "IS", "USER_NAME": "Main occupied", "command": "close"},
                       "unoccupied": {"DECADDR": "40", "JMRIPREFIX": "IS", "command": "throw"}},
              "3-5":  {"name": "OS Switch 3"}},
 "masts":    {"12C":  {"name": "Mast 12C", "template": "double", "pantype": "LAMP2"}}}
```

- **switches**, by label, or `label/alias` for one of several switches with that number (a key that is not a whole label splits at its last `/`; labels compare as text): `block` names its OS block (or, for a double crossover, `corners` names a block for each leg A to D and `X` the middle, by default `OS <number>a` to `d` and `OS <number> X`, and `"corners": "one"` or a `block` makes it one OS block; see 0.1.31 and 0.1.41) (switches of one number given different blocks keep apart; switches given one block name share one block, and that name is never suffixed or shared with another block), `normal` picks the CATS normal leg (default B; for a single crossover half, its leg that is not the link to the other half), `label` replaces the number shown at its points (such as 23A and 23B for the two halves of a crossover), and `routes` gives each leg's IOSPECs (`ROUTECOMMAND`, `SELECTEDREPORT`, `NOTSELECTEDREPORT`). Double crossovers take a `block` or `corners`, not both.
- **blocks**, by the panel's block name (after the switches' `block`s): `name` renames it, so a short track between two switches can join one of their OS blocks. Blocks end up as one only when the bindings name them all (a block keyed in `blocks` or named by a switch `block` keeps its own name); renaming onto a block the bindings do not mention stops the run, and each merge is reported; `station`, `discipline`, and the `occupied` and `unoccupied` IOSPECs.
- **masts**, by the name in the signals layer, field or planned (virtual masts are not drawn): `name` is the SECSIGNAL text (the layout's mast name), `template` the physical signal template, `pantype` the panel lamp (default `LAMP` and the head count). Each mast goes on the block boundary nearest where it stands on its run, on the edge of the block it protects (the side its move is heading for), facing out of that block, on the right-hand side of the move.
- An IOSPEC holds `DECADDR`, `JMRIPREFIX`, `USER_NAME` (also `JMRIDEVICE`, `EXIT_CMD`, `DELAY`) and its `command`, `close` or `throw`. Keys starting with `_` are notes. A name the panel does not have, or an unknown field, stops the run.

`--templates-from DESK.xml` copies the `SIGNALTEMPLATE`, `JMRINAME` and `COLORDEFINITION` elements of an existing CATS panel, so the masts' templates and the IOSPECs' device prefixes resolve and the colours match (CATS paints a block with no occupancy sensors in its DARK colour, grey by default); a mast naming a template the panel has no `SIGNALTEMPLATE` for stops the run. The cell rules are in [`skills/schematic-maps/references/cats-grid.md`](skills/schematic-maps/references/cats-grid.md).

## Layout Editor panel

`schematic le` writes a JMRI Layout Editor panel (one `<LayoutEditor>` element) that looks like the sheet: every band stacked on one panel, straight rows, yards leaving at the drawn slopes and running level, every corner rounded by a circular arc, each turnback a half circle, helix ends marked by a circle and connector letters in a circle, with switch numbers, track names, station names and band titles as labels and a block contents icon per block (the train in it), each placed in a clean spot sized as JMRI draws it (the label layer; `le_labels` options, a run with no room for one stops and names it). One grid unit is 36 pixels (`--cell`, `--row`), or `--fit WIDTHxHEIGHT` shrinks the grid until the panel and its window frame fit a window that size, so it opens at 100% zoom (fonts keep their size); with the `equal_width` preference a narrower band is stretched along its length as on the sheet. It writes turnouts (right or left hand as drawn, the drawn straight leg as leg B and `continuing` set so the normal route stays on the band's leg B), a double crossover as a DOUBLE_XOVER, two switches of one number (labelled alike, or lettered A and B) joined C to C, or halves lettered A and B joined B to C, as one single crossover closed on both through tracks, track segments with `mainline` set from the main route (Layout Editor draws main track wider), anchors, end bumpers, and a hidden track segment joining each connector letter and helix track that appears on two drawn bands, so the panel is one connected railroad. `--names` binds it to existing JMRI objects: by band key, turnout names, OS blocks, the normal leg, each track's blocks in order (a track with several blocks is cut at their real lengths when `lengths` gives them, so a throat block sits at its own end, else into equal lengths), the leg each switch takes as Layout Editor leg B (`leg_b`, so an old panel's leg letters hold), an old panel's idents for its turnouts, boundary anchors, end bumpers and one-segment blocks (`idents`, so it can replace that panel), and masts by the facing and protected blocks they should resolve to, so each lands in the slot JMRI reads them from, with an icon on the right-hand side of the train. The CATS mast rules carry over: the boundary anchors of one control point's masts slide along their own track, between the same two blocks, so each direction stands in one column (a gantry), and each icon takes its clearest spot, off turnouts, other icons and labels; without it, blocks are named after the tracks and turnouts are left unnamed. It writes no sensors or block beans: add the turnouts and blocks to the tables file the panel goes into, close JMRI first, and check the panel with Layout Editor's Check menu once it loads. The mapping is in [`skills/schematic-maps/references/le-panel.md`](skills/schematic-maps/references/le-panel.md).

In 0.1.31 (CATS), a double crossover's switch binding may give `corners`: a block name for each band leg A to D, and `X` for the middle of its X. The panel then draws the crossover as a block per corner, as a Layout Editor double crossover with a block per corner is: each corner holds its points, half of each through track and the first piece of its diagonal, and the two crossing cells are the middle block. CATS parts a block neither at switch points nor where two blocks meet one side of a crossing, so the X must be two cells deep: on a one cell per unit panel the rows between its tracks are opened by one, the rows below move down, and any other slope across the opened row takes a short vertical jog there. Without `corners` a double crossover stayed one OS block, as in 0.1.29, until 0.1.41 made the corners the default.

In 0.1.30, `le.panel(..., name_room=[band key, ...])` lets a band out in the same pass where a named track's straight is shorter than its name, while the band stays no wider than the widest band, so a crowded band with width to spare places its names.

In 0.1.29, `le.panel(..., mast_room=[band key, ...])` lets a band's drawing out along its rows where a mast's icon has too short a straight before its boundary, or no clean spot there (sloped lines through a switch keep their slope, so no switch changes shape); and a `names_last` name (or an `optional_block_contents` icon) left out is tried again first, kept there when every other item still finds a spot.

Also in 0.1.29 (CATS): a double crossover takes switch routes in the bindings (one turnout moves all four points: B along the through tracks, C into the X; it stays one OS block, since CATS cannot part a block at points or a crossing), and `panel(..., helix_blocks="apart")` (`--helix-blocks apart`) makes a joined helix track a block on each band, parted at the join, where the layout's detection parts there.

Unreleased: Layout Editor geometry knobs are preferences, read only by `le` (`schematic/le_prefs.py`): a band's `le_shift` (part of a band moved whole columns along), `le_longer_straights` (a track's straight lengthened at one switch by moving its bend) and `le_crossover_angle` (every crossover at one angle), the page's `le_title_clear` (gaps between bands that fit the drawing, with `band_bottoms` for a caller's own items) and `le_stretch` (`le.stretched` and `le.check_stretch`, for a panel widened to a window's shape), and a band's `le_labels` `extra_steps` and `extra_follow` (caller's items stepped along one slope). See [`skills/schematic-maps/references/le-panel.md`](skills/schematic-maps/references/le-panel.md).

In 0.1.28, a band's names may give a double crossover a block per corner (`xover_blocks`, by band leg; the four must differ): with one or two blocks JMRI records a through path between the two legs on one side, and Signal Mast Logic discovery then pairs masts across it.

In 0.1.27, a Layout Editor mast may name the turnout leg it stands on (`leg`: normal or diverging), for two masts with one facing and protected block, as at the two ends of a balloon loop; and `le_labels` may list `optional_block_contents`, blocks whose contents icon is left out (and logged) when no clean spot is left for it; and a band's names may say `"joins": "none"` to draw its connector and helix ends unjoined.

In 0.1.26, the row search works out each move's cost from the tracks it moved and reuses solves it has done, so a solve takes about half the time; the cache keys only the code each result runs, keeps Layout Editor panels and fit grids, and leaves the title block's fields out of the solve's key. Drawings are the same byte for byte.

In 0.1.25, also: a crossover drawn tight beside one drawn as turnouts is bounded by those turnouts' legs; a split crossover's moved half is checked along its track, so one slid past its far end stops; `split_crossovers` work with `fit`; a double crossover takes a `crossover_run` shorter than as drawn; a crossover rounded to whole pixels past its room is logged (over 1.5 px it stops); and a `lamp_columns` track with no level piece at its column stops naming the track. Known limit: a double crossover's room does not reserve its far switch's leg; the run stops (a track shorter than its switches' legs) if that leaves a track too short.

Since 0.1.24 a track end joined to another band is an anchor numbered among the end bumpers (`AGE<n>`), not among the other anchors, so joining bands renumbers nothing else of either. A panel built before then numbered those ends `AG<n>`, so the generated `AG<n>` idents of the anchors after them change: a saved reference to one of those (a script, an audit, a contract naming a generated ident) must be read again from the new panel. Given idents (`idents`) are unaffected.

## The example

`tests/example.py` writes a made-up railroad, the Pine Hollow & Eastern, as every file the tool reads: a plan export, plan parts, a Layout Editor panel, switch numbers, block lengths and layer files. It has a yard ladder, a double crossover, a loop, two levels joined by a rise and a helix track, a switch added by the overrides, a switch in the plan that was never built, and masts on a turnout leg, an anchor and a ladder link. It is track only and invented for the tests. `tests/golden/` holds the fingerprints of its drawings.

Where two tracks join the same two switches, an override edit that names the pair stops and asks for the leg instead of taking the longer track: `"port": "C"` beside `on`, a third item in `onto` (`["3", "4", "C"]`), a fourth in a `name` entry, and the leg in `track_directions`.

## Where it came from

The layout engine, readers and label placer were proved as a spike on one real railroad, then rebuilt here as tested modules. The generation rules replace the hand hints the spike needed: the main level (R5), ladders (R6), rows for tracks that run side by side (R7), hands from the overrides (R10) and labels that claim grid room on their own track (R12).
